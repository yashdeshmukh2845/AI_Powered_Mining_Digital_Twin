# Orebit Synthetic Drillhole Datasets

Three synthetic drillhole datasets for teaching, software tests, and tutorials:
**epithermal gold**, **nickel laterite**, and **alluvial tin**.

All measurements are generated by the models in `_generator/`; they are not
observations from a mine or exploration project.

**Licence: CC BY 4.0.** Use them in courses, papers, blog posts, benchmarks,
and commercial software. Just credit Orebit.id.

---

[Download all CSVs (source ZIP)](https://github.com/ghoziankarami/orebit-datasets/archive/refs/heads/main.zip) ·
[Use with GeoSuite](docs/USE_WITH_GEOSUITE.md) · [Orebit guides](https://orebit.id/docs.html)

Reading or importing the CSVs needs no Python installation. Python and the
pinned dependencies are only needed for generators and validation.

## The three datasets

| | `01-emas-epitermal` | `02-nikel-laterit` | `03-timah-placer` |
|---|---|---|---|
| Commodity | Gold–silver | Nickel–cobalt | Tin |
| Style | Low-sulphidation epithermal vein | Ni laterite over ultramafic | Alluvial placer (cassiterite) |
| Indonesian analogue | Pongkor / Cikotok, West Java | Sorowako / Halmahera | Bangka–Belitung |
| Geometry | Steep tabular vein, dip 75° | Sub-horizontal layered profile | Buried palaeochannel |
| Drilling | 103 angled holes, 20,187 m | 350 vertical holes, 8,195 m | 500 vertical holes, 5,867 m |
| Pattern | 30 m sections, 4 holes deep | 100 m grid + 50 m infill | 100 m lines × 25 m holes |
| Sample | 1 m in vein / 2 m waste | 1 m | 1 m |
| Assay rows | 11,526 | 8,278 | 5,990 |
| Grade CV | **1.66** (in vein) | **0.28** (in saprolite) | **1.42** (in kaksa) |
| Grade unit | g/t | % | kg/m³ |

The grade distributions differ between the vein, laterite profile, and basal
placer layer, allowing the same workflow to be tested on contrasting inputs.

## Files

Every dataset uses the same four-file layout, so a script written for one runs
on the others:

```
collar.csv   BHID, XCOLLAR, YCOLLAR, ZCOLLAR, TD
survey.csv   BHID, AT, AZ, DIP
assay.csv    BHID, FROM, TO, <elements...>, SG or BD_TM3
litho.csv    BHID, FROM, TO, LITH [, ALT]
```

- Coordinates are **metres**, in a plausible UTM zone for each region
  (WGS 84). Elevation is metres above sea level, Z positive up.
- `DIP` is **positive downward**, 90° = vertical down.
- `AT`, `FROM`, `TO`, `TD` are downhole metres.
- Grade columns carry their unit in the name (`AU_GPT`, `NI_PCT`, `SN_KGM3`).
- Blank cells indicate missing values, not zeros.

Each dataset folder has its own README with the full column dictionary, the
geological model behind it, and the statistics.

```
orebit-datasets/
├── 01-emas-epitermal/     collar · survey · assay · litho · README
├── 02-nikel-laterit/      collar · survey · assay · litho · README
├── 03-timah-placer/       collar · survey · assay · litho · README
├── figures/               deposit-styles.png · grade-distributions.png
├── _generator/            the models that produced everything
│   ├── common.py            noise fields + minimum-curvature desurvey
│   ├── gen_emas.py          gold
```

## Quick start

Clone or download this repository, open a terminal in its root, and install the
example dependencies in a virtual environment:

```bash
git clone https://github.com/ghoziankarami/orebit-datasets.git
cd orebit-datasets
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r _generator/requirements.txt
```

```python
import pandas as pd

d = "02-nikel-laterit"
collar = pd.read_csv(f"{d}/collar.csv")
survey = pd.read_csv(f"{d}/survey.csv")
assay  = pd.read_csv(f"{d}/assay.csv")
litho  = pd.read_csv(f"{d}/litho.csv")

# tag each assay interval with the horizon it sits in
m = assay.merge(litho, on="BHID", suffixes=("", "_l"))
m = m[(m.FROM >= m.FROM_l) & (m.TO <= m.TO_l)]

print(m.groupby("LITH")[["NI_PCT", "FE_PCT", "MGO_PCT"]].mean())
```

```
      NI_PCT  FE_PCT  MGO_PCT
LITH
BRK     0.29    6.58    36.91
LIM     1.19   42.06     3.78
OVB     0.72   49.22     0.81
SAP     1.72   15.10    18.13
```

Downhole coordinates are not included as a column — desurvey them yourself, or
reuse `desurvey()` from `_generator/common.py`, which implements minimum
curvature against the same convention the files use.

## What has deliberately been left in

The generators include documented missing samples and incomplete holes:

- **Unassayed casing intervals** at the top of every gold hole
- **Below-detection values** reported at half the detection limit
  (11.9% of gold samples)
- **Lost samples** — 41 nickel intervals with no assay
- **Abandoned holes** — 26 tin holes stopped before reaching bedrock, and
  8 nickel holes stopped short
- **Uneven sample lengths** where the last interval meets total depth
- **Holes that missed** — 4 of 103 gold holes do not intersect the vein

What is *not* in there: overlapping intervals, negative grades, orphan
samples, duplicate hole IDs, or assays past total depth. Those all pass clean
(`_generator/validate.py` checks each one). For validation exercises, make a separate copy and record each deliberately
introduced error.

## Regenerating

```bash
cd _generator
python3 gen_emas.py      # gold
python3 gen_nikel.py     # nickel
python3 gen_timah.py     # tin
python3 validate.py      # integrity + plausibility checks
```

Install **numpy** and **pandas** in a Python environment first. Fixed seeds
make the output reproducible; changing a seed creates another model realisation.

`common.py` holds the two shared pieces: a multi-octave value-noise field for
spatially correlated geology, and a minimum-curvature desurvey routine.

## Limitations

- These are **models, not measurements**. They reproduce the statistical and
  spatial character of each deposit style. They do not reproduce the messiness
  of a real database, the ambiguity of real logging, or any specific orebody.
- Grade continuity is imposed by the generator, so a variogram fitted to this
  data recovers the model that made it. That is fine for teaching method and
  testing software; it is not evidence about how any real deposit behaves.
- **Never** use these as an analogue or supporting data in a public resource
  or reserve statement under JORC, NI 43-101, SNI, or any other code.

## Bahasa Indonesia — ringkasan

Tiga dataset bor **sintetis sepenuhnya** dengan lisensi terbuka, dibangun
mengikuti gaya endapan yang relevan di Indonesia: **emas epitermal**,
**nikel laterit**, dan **timah aluvial**.

Semua nilai dihasilkan oleh model dalam `_generator/`, bukan pengukuran
lapangan atau data perusahaan.

**Lisensi CC BY 4.0** — bebas dipakai untuk kuliah, publikasi, tutorial,
benchmark, sampai software komersial, cukup cantumkan kredit ke Orebit.id.

Yang membuat koleksi ini berguna: ketiganya punya karakter data yang berbeda
total. Emas memiliki variasi kadar tinggi (CV 1,66), nikel laterit halus dan berlapis
(CV 0,28), timah terkonsentrasi tipis di dasar paleochannel (CV 1,42). Satu
alur kerja harus sanggup menangani ketiganya.

Format keempat filenya seragam (`collar`, `survey`, `assay`, `litho`) dengan
konvensi DIP positif ke bawah, satuan meter, dan satuan kadar tertulis di nama
kolom. Rincian lengkap tiap dataset ada di README masing-masing folder.

Beberapa ketidaksempurnaan **sengaja dipertahankan** supaya terasa realistis:
interval casing yang tidak diassay, nilai di bawah limit deteksi, sampel
hilang, lubang buntu, dan lubang yang meleset dari urat. Semuanya
terdokumentasi. Tetapi tidak ada overlap interval, kadar negatif, atau assay
melewati TD — itu semua lolos bersih.

**Jangan** memakai dataset ini sebagai analog atau data pendukung dalam
pelaporan sumberdaya/cadangan publik (JORC, NI 43-101, SNI). Ini untuk
pendidikan, pengujian software, dan demonstrasi saja.

## Validation in CI

`Dataset validation` checks the committed CSVs, reference statistics and negative regression fixtures. Run the same checks locally:

```bash
python _generator/validate.py
python _generator/check_readme.py
python -m unittest discover -s tests -v
```

Both checker commands return a nonzero exit status when their checks fail. The statistics checker compares CSV values to explicit reference numbers in its script; it does not parse every number in arbitrary README prose. These checks cover data integrity and documented model statistics, not independent geological validation.
